# Evaluation

[简体中文](zh/evaluation.md)

`/snapcompact benchmark` **explicitly starts model requests**: at most four auxiliary calls for original-text questions, native-summary generation, native-summary questions and local-visual questions. If visuals cannot be generated safely, that arm is skipped, not replaced with a text call labeled as vision.

The bundled synthetic fixture is used by default; private session history is not read or uploaded. Evaluation uses the current route without changing provider configuration, the current task or the conversation surface. Its report is retained in the human-command result.

## Reported metrics

- Exact answer matches for Chinese constraints, paths, commands, numbers, Python indentation, variable spelling, final corrections and next action.
- Provider-reported input/output/cacheRead/cacheWrite usage, preserved separately. Missing fields are not invented.
- Prompt totals follow DSH's contract: input + cacheRead + cacheWrite, not totalTokens, which can also include output.
- Summary generation overhead is reported separately and must be amortized over later turns.
- Request latency, summary/visual preparation latency, selected frame count and dimensions, generated bytes, truncated characters, and estimated image-checkpoint cost.
- A frame-only marker question in the synthetic fixture checks that the model reads the bitmap middle, not just the exact head/tail text.

## Two cost axes

Token economy has a one-time axis and a steady-state axis. The local visual path has no generation call but a larger checkpoint; a native summary pays a summarizer call once and then carries a smaller context. Report both. Comparing a summary's per-turn read with a visual checkpoint's per-turn read omits the summarizer call; comparing only first-turn totals hides the visual checkpoint's larger steady state.

## Interpretation limits

A fixed exact-match fixture is reproducible, not representative of every language or long-running project. A single run does not automatically reconfigure the plugin or prove savings on every route or turn horizon. Standalone fixture requests also differ from a full routed conversation's system/tool envelope.

The visual arm is the production local-rendering path: bounded head/tail text plus bitmap frames, with no handoff summary. The fixture places exact facts in the frame middle (not only in the head/tail text) so the score reflects bitmap readability. Cache reuse, output length and model-specific billing still affect comparisons; a smaller estimated checkpoint is not proof of monetary savings or preserved task information.

Visual arms can be skipped for missing vision metadata, undeclared pricing, unreadable request resizing or an insufficient frame budget. That is a safety fallback, not evidence of successful image comprehension. A response without provider usage is marked unmeasured rather than used for a fabricated token-saving claim.

For real-project evaluation, obtain permission for both the history and destination provider, then prepare redacted fixtures. Never commit private session logs as public benchmark assets.
