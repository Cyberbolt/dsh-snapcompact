# 对照评测

执行 `/snapcompact benchmark` 是**显式发起模型调用**，最多四次辅助调用：原文问答、原生摘要生成、摘要问答、图片混合 checkpoint 问答。无法生成图片时跳过视觉问答，不把文本问答冒充视觉成绩。

默认仅使用随包合成语料，不读取或上传当前私密历史。模型沿用当前会话路由，评测不改变 provider 配置、当前任务或会话 surface。报告留在人类命令结果中。

## 看哪些指标

- 各组精确答案匹配数：中文约束、精确路径、命令、数字、Python 缩进、变量、最终纠正和下一步。
- provider 返回的 input/output/cacheRead/cacheWrite 等 usage，分别保留，不凭空补缺失字段。
- 实际 prompt token 依照 DSH 合同合计 input + cacheRead + cacheWrite；不是 `totalTokens`（它可能包含输出）。
- 原生摘要的额外调用成本独立列示，不能只比较最终 checkpoint 而忽略生成成本。
- 请求耗时、图片候选的估算成本。不同缓存命中率、输出长度和收费模型会影响比较。

## 解释边界

视觉组复用原生摘要作为文本基线，以隔离补充图片的效果；不声称逐字节复现所有生产交接摘要及 checkpoint 包装。

固定语料与精确匹配是可复现基线，不代表真实长项目的一切语言和任务。首版不自动用一次评测结果修改用户配置，也不承诺某模型总有2倍实际收益。

图片路径可能被安全策略跳过，尤其是不声明视觉能力、没有图片计价、请求会缩放字形的路由。这是安全回退，不是渲染成功的证据。缺 usage 就标记未测量，不报告虚构的 token 节省。

需要另行比较真实项目时，先获得使用相关历史和目标 provider 的授权，再准备脱敏语料；不要将私密会话直接加入公开测试 fixture。
