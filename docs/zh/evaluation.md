# 对照评测

执行 `/snapcompact benchmark` 是**显式发起模型调用**，最多四次辅助调用：原文问答、原生摘要生成、原生摘要问答、纯本地视觉 checkpoint 问答。无法生成图片时跳过视觉问答，不把文本问答冒充视觉成绩。

默认仅使用随包合成语料（`engineering-recall-v2`，40 题），不读取或上传当前私密历史。10 个 `probes` 会替换固定位置的 padding 行，让事实落在跨多帧的位图中段；其余题目覆盖精确头尾文本。评分只裁掉答案外层空白，保留内部缩进。模型沿用当前会话路由，评测不改变 provider 配置、当前任务或会话 surface。报告连同各组未命中题键一起留在人类命令结果中。

## 看哪些指标

- 各组精确答案匹配数：中文约束、精确路径、命令、数字、Python 缩进、变量、最终纠正和下一步。
- provider 返回的 input/output/cacheRead/cacheWrite 等 usage，分别保留，不凭空补缺失字段。
- 实际 prompt token 依照 DSH 合同合计 input + cacheRead + cacheWrite；不是 `totalTokens`（它可能包含输出）。
- 原生摘要的额外调用成本独立列示，不能只比较最终 checkpoint 而忽略生成成本。
- 请求耗时、视觉准备耗时、选中帧数和尺寸、生成字节、截断字符数，以及图片 checkpoint 的估算成本。
- 10 个帧中段 probe 用来确认模型读的是位图，而不只是头尾精确文本；报告会列出每组未命中的题键。
- 纯本地密度检查（`src/rendering/density.test.ts`）固定帧数、每帧字符数和 PNG 字节数，不发起模型调用，也不衡量召回率。

## 两个成本轴

token 经济性要分两个轴：一次性生成成本和稳态携带成本。本地视觉路径没有生成调用，但 checkpoint 更大；原生摘要先付一次生成调用，之后每轮携带的上下文更小。两个轴都要报告：只比较摘要的每轮读取量会漏掉生成调用，只比较首轮总量会掩盖视觉 checkpoint 更大的稳态占用。

## 解释边界

视觉组使用生产用的纯本地路径：有界头尾文本加位图帧，不调用模型摘要。fixture v1 的计分事实全部落在精确 tail，8/9 可能只靠文本读出；v2 把 10 个 probe 放进中段，分数才真正依赖图片识读。

固定语料与精确匹配是可复现基线，不代表真实长项目的一切语言和任务。首版不自动用一次评测结果修改用户配置，也不承诺每个路由、每种使用时长都有节省。

图片路径可能被安全策略跳过，尤其是不声明视觉能力、没有可用价格估算、请求会缩放字形或帧预算不足的路由。这是安全回退，不是渲染成功的证据。缺 usage 就标记未测量，不报告虚构的 token 节省。

需要另行比较真实项目时，先获得使用相关历史和目标 provider 的授权，再准备脱敏语料；不要将私密会话直接加入公开测试 fixture。
